## Overview
This repository hosts `magicsunday/webtrees-module-base`, a shared PHP library consumed by `webtrees-fan-chart`, `webtrees-pedigree-chart`, `webtrees-descendants-chart`, and `webtrees-statistics`. It contains the common processors (Date, Name, Image, Place, Fact), models (Symbols, NameAbbreviation, PlaceStyle, PlaceFormatSpec, PlaceFormatChoice, NameSegment, NameSegmentKind, FactView, NodeData), locale support (`IsoCountryMap`), and module helpers (VersionInformation) those modules use. The three chart modules render genealogy charts; the statistics module renders a statistics dashboard and consumes only the shared core plus `IsoCountryMap`. No JavaScript, no asset pipeline, pure PHP.

Not all of this is consumed by every consumer. The statistics module uses only the shared core plus `IsoCountryMap`, and the chart modules adopt the place subsystem, the compact date API and the fact components as they need them. A component can live in the base before its second consumer exists, so that the consumer adopts it without a namespace move, as the statistics module did with `IsoCountryMap`. To see which module uses a class, search the sibling checkouts, for example `grep -rl 'ModuleBase.Processor.PlaceProcessor' ../webtrees-*/src | grep -v '^../webtrees-module-base/'`.

## Setup/env
- PHP 8.3 - 8.5 with extensions `dom`, `intl` and `mbstring` is required; composer installs dependencies into `.build/vendor` and binaries into `.build/bin`.
- The most common dev workflow is via `make link-base` from a sibling chart module: that symlinks `.build/vendor/.../webtrees-module-base` in the chart module to a sibling clone of this repo, so edits here are immediately picked up by the consumer.

## Running the test suite

This library has no module-local container. PHP runs through the webtrees-docker
buildbox, which provides ext-intl (required since 3.0.0):

    cd /path/to/webtrees-docker && docker compose run --rm buildbox bash -c \
        'cd /var/webtrees/app/vendor/magicsunday/webtrees-module-base && composer ci:test'

Substitute `composer install`, `composer update` or `composer ci:cgl` for the last
command as needed. CI does not use Docker at all — the workflow installs PHP
directly via setup-php.

### Why the advisories of the webtrees pins are ignored

This package requires `fisharebest/webtrees` for its API, to develop and test against and at runtime to drive on the host install (for example `Module/VersionInformation`'s release-version check runs on webtrees' bundled `guzzlehttp/guzzle`). It is a **library consumed into** an administrator's own webtrees install, and the release artifact ships this package's own files without any vendored dependency, so it neither vendors nor distributes webtrees' transitive dependencies. They are exact-pinned by each webtrees release, not chosen by us, not patchable by us, and upgraded by the administrator's webtrees, not by this package.

Composer's advisory policy blocks *resolution*, not merely the `composer audit` report (`--no-audit` / `COMPOSER_NO_AUDIT` suppress only the report). So whenever a pinned dependency picks up an advisory, every install and CI run of this package fails for a vulnerability that cannot reach anyone through us. That concerns the resolution on the developer side only. Whether a host is exposed at runtime, as with Guzzle on the update-check path, depends on the host's webtrees install and is not decided by these entries. `config` applies only to the root package, so consumers are unaffected.

### Convention for new advisory ignores

Before adding an entry, check the following. Is the package a direct dependency (`composer why`)? Does a public fix exist? Does an exact pin of webtrees alone block that fix (`composer why-not <package> <fixed version>`)? Update instead of ignoring whenever the fix is reachable.

- An advisory that webtrees' exact pin keeps unresolved is ignored by its **advisory ID** under `config.policy.advisories.ignore-id`, so later advisories on the same package keep blocking. Never ignore by package name under `ignore`, because that also hides every later advisory of the package.
- The reason starts with a prefix that says why the entry exists, followed by the CVE and the condition for removing it. `UPSTREAM-PINNED:` marks a fix that exists publicly but is held back by the exact pin of webtrees. `ACCEPTED:` is reserved for a conscious risk acceptance with a low severity and no attack path in this package.
- Remove the entry once the supported webtrees range no longer pins an affected version.

## Build & tests
- **`composer ci:test` MUST run before every commit** — catches phplint, PHPStan (level max), the phpat subject-liveness check, Rector, PHPUnit, PHP-CS-Fixer, the coding-standard template lockstep and Deptrac issues before they reach GitHub CI.
- Individual checks: `composer ci:test:php:phpstan`, `composer ci:test:php:unit`, `composer ci:test:php:cgl`, `composer ci:test:php:rector`, `composer ci:test:php:lint`, `composer ci:test:php:psr4`, `composer ci:test:php:phpat-subjects`, `composer ci:test:php:templates`, `composer ci:test:php:deptrac`.
- Single PHPUnit test: `composer ci:test:php:unit -- --filter TestClassName`.
- A fresh checkout needs `npm ci` once before `composer ci:test`, because the copy-paste step runs the installed `node_modules/.bin/jscpd`.
- Auto-fix: `composer ci:cgl` (PHP-CS-Fixer), `composer ci:rector` (Rector).
- Some tests of the resolver and the writer run the gettext tools (`msgcat`, `msgattrib`, `msgmerge`, `msgfmt`) and skip themselves where one of them is missing. They are the ones that call `GettextWorkspace::toolsAvailable()`. A green run without the tools therefore did not run them. The CI workflow installs the tools in a step of its own before the PHPUnit step.
- No Makefile. This library has no JS build, no translation catalogue of its own (the fixture catalogues under `tests/` are compiled by hand with `msgfmt`) and no build step that produces a release artifact, so every command it needs is a composer script run through the buildbox (see above). To force a full regeneration, delete the generated paths directly: `rm -rf .build node_modules`, followed by `npm ci`.

## Architecture

### Layout
```
bin/
  resolve-fuzzy   — starter for the catalogue resolver, installed by Composer as a binary for the consuming modules
  write-translations — starter for the translations writer, installed the same way
resources/views/ holds the shared PHP templates (detail-panel.phtml, help-popover.phtml), rendered by the chart modules through SharedViews
src/
  Catalogue/      — resolver for the fuzzy entries and writer for the translations of the translation catalogues
  Contract/       — local interfaces required by processors (e.g. ModuleAssetUrlInterface)
  Facade/         — traits for chart DataFacade implementations (module/route injection)
  Model/          — value objects, enums and the person DTO (Symbols, NameAbbreviation, PlaceStyle, PlaceFormatSpec, PlaceFormatChoice, NameSegment, NameSegmentKind, FactView, NodeData)
  Module/         — module-level helpers (VersionInformation)
  Processor/      — DateProcessor, NameProcessor, ImageProcessor, PlaceProcessor, FactResolver
  Support/        — plain helpers (CompactDateFormat, TextDirection, PlainText)
  Support/Locale/ — locale-aware helpers (IsoCountryMap)
  Testing/        — reusable PHPUnit test cases the consuming modules extend (AbstractCatalogueStructureTestCase)
  Traits/         — shared ModuleCustomTrait / ModuleChartTrait helpers for consuming modules
  View/           SharedViews, which registers the view namespace for resources/views/
tests/
  bootstrap.php   — harness only; belongs to no source class, so it stays at the root
  Architecture/   — phpat rule providers, not PHPUnit tests (see the mirror exception below)
  Bin/            — tests of the bin/ starter, which has no counterpart under src/
  Double/         — test doubles that are no test themselves (no *Test.php)
  fixtures/       — data files the tests read (the fixture catalogues, and the catalogue the resolver tests run on)
  <mirror of src/> — every *Test.php sits at the path its subject has under src/
                     (src/Processor/DateProcessor.php → tests/Processor/DateProcessorTest.php)
```

### Processors
- **`DateProcessor`** — generation-aware date formatting. Public methods include both the legacy locale-aware API (`getBirth*`, `getDeath*`, `getLifetimeDescription`) and the newer compact format API (`getFormatted*`, `get*Full`, `getCompactLifetimeDescription`) that the fan chart uses to keep deep-generation labels short. Marriage dates are served by the compact API only; the legacy `getMarriageDate()` / `getMarriageDateOfParents()` were removed in 3.0.0 (no consumer called them). `getBirthDate()` / `getDeathDate()` return **plain text designed for a text sink** (SVG `<text>`, a JS string): the accessor strips webtrees' display markup and decodes its entities, so a consumer rendering the value into HTML must escape it at that sink. The static `formatFactDate()` returns the text of the date of any fact: the compact format for a complete date and the webtrees wording, as plain text with single spaces, for a partial, qualified or ranged one, so a qualifier such as "about" stays in the text. A date without a year, such as "12 MAY", gives an empty text, qualifier included, because webtrees cannot place it on a calendar.
- **`NameProcessor`** — name extraction from webtrees name HTML. Splits first/last/preferred names, handles starredname spans, alternative names, married names. DOM/XPath based. `getNameSegments()` returns the name as an ordered list of `NameSegment` objects (given names with particles, nickname, surnames, optional bracketed married surname), so a consumer draws the segments instead of locating tokens in the flat name.
- **`ImageProcessor`** — highlight image + silhouette URL resolution. Constructor requires `ModuleCustomInterface & ModuleAssetUrlInterface` (the marker interface ensures the module exposes `assetUrl()`, which lives on `ModuleCustomTrait` and is invisible to the `ModuleCustomInterface` type alone).
- **`PlaceProcessor`** — extracts and shortens birth/death/marriage place names for chart labels, driven by a resolved `PlaceFormatSpec`. Supports `PlaceStyle::Full` (unchanged), `PlaceStyle::Levels` (keep a fixed number of hierarchy levels, from either end), `PlaceStyle::CityCountry` (keep the first and last segment; resolves the country segment via `IsoCountryMap` when it is a recognised country name), and `PlaceStyle::CityIso2` / `CityIso3` (the same, but rendering the resolved country as its ISO-3166 alpha-2 / alpha-3 code).
- **`FactResolver`**: resolves the facts a chart box shows, one slot per row except for a family tag, for the chart modules. Slot 0 is the first existing birth equivalent (BIRT, CHR, BAPM) and slot 1 the first existing death equivalent (DEAT, BURI, CREM), each `null` when the individual has no visible fact for it. When the caller asks for the optional facts, the marriage (`MARR`) and the divorce (`DIV`) are added unless the preference names the tag itself, the marriage behind the death slot and the divorce behind the marriage, and the optional tags of the tree preference `CHART_BOX_TAGS` follow in their order. A marriage or divorce tag (the `Gedcom::MARRIAGE_EVENTS` and `Gedcom::DIVORCE_EVENTS` of webtrees) is a fact of the family, so `spouseFamilies()` is read and every family with the fact gives one entry that names the other spouse in `partner`. The class docblock of `FactResolver` holds the rules for a preference that names the marriage or the divorce itself, for the null entries and for the order. Dates go through `DateProcessor::formatFactDate()`, places through `PlaceProcessor` with the configured `PlaceFormatSpec`. The `PlaceProcessor` is built inside the call for the individual, so no processor of another person can be passed in.

### Models
- **`Model/Symbols`** — backed enum for genealogical symbols (Birth ★, Death †, en-dash separator, MarriageDateUnknown sentinel).
- **`Model/NameAbbreviation`** — backed enum + `resolve()` helper for the chart-label name-abbreviation strategy (auto / given / surname). The strategy enum lives here, the label rendering stays in the chart module.
- **`Model/PlaceStyle`** — enum for the way a place name is shortened (`Full`, `Levels`, `CityCountry`, `CityIso2`, `CityIso3` — the last two render the resolved country as an ISO-3166 alpha-2/alpha-3 code instead of its name). Distinct from `PlaceFormatChoice`: "Automatic" is a settings source, resolved before it reaches a formatter.
- **`Model/PlaceFormatSpec`** — final readonly value object holding a fully resolved place-formatting instruction (`style`, `levels`, `fromEnd`) with no configuration lookups left to perform; validates the level count in its constructor.
- **`Model/PlaceFormatChoice`** — backed enum for the place-detail options a module offers in its configuration and the value persisted in the module preference. Deliberately free of display labels — the consuming module supplies those at its own `I18N::translate()` call sites.
- **`Model/NodeData`** — the person DTO of the linked tree charts. Its `jsonSerialize()` shape, key order included, is the JSON contract to the front end and pinned by a test, so a change is a deliberate contract change. It carries the name as `NameSegment` objects next to the flat name. The underlying individual is held for the facade and stays out of the serialised form. The optional `facts` list (`FactView` or `null` entries, as the `FactResolver` returns them) is appended as the last key and only when the list is not empty, so a consumer that never sets facts keeps its payload and key order. A list of empty slots is serialised.
- **`Model/FactView`**: one fact of a chart box (`tag`, `label`, `date`, `place`, `placeFull`, `value`, `partner`, `sortDay`) for a text sink. `partner` is the plain text name of the other spouse as webtrees shows it to the viewer for an event of a family. For a private spouse it is a placeholder when the tree shows private relationships and empty when it does not, and it is empty for an event of the person. `sortDay` is the Julian day number of the first day of the date as written, without regard to a qualifier such as "after" or "before", zero without a usable date, and lets a consumer order facts by time. Label, date and partner are reduced to plain text, and so is the name of a linked record that stands in for a pointer value, the place is formatted by the configured style, the full place and any other value are not reduced, so a consumer escapes all of them at the HTML sink. `tag` is the concrete tag that was found, for the birth slot possibly CHR or BAPM. The serialised keys follow the constructor order.
- **`Model/NameSegment`** / **`Model/NameSegmentKind`** — one drawable part of a name (`label`, `kind` given/surname/nickname/married, `isPreferred`) and its role enum. The serialised kind is the enum's backing value.

### Support
- **`Support/CompactDateFormat`** — derives a locale-aware, compact (numeric) date format string from the CLDR/ICU short-date pattern of a locale, for `DateProcessor`'s compact API.
- **`Support/TextDirection`** — resolves script direction (LTR/RTL) for arbitrary strings.
- **`Support/PlainText`**: reduces webtrees markup to plain text (strips the tags, decodes the entities). The result may contain characters that are unsafe in HTML, so a consumer escapes it at the HTML sink.
- **`Support/Locale/IsoCountryMap`** — maps free-text country names from GEDCOM PLAC lines to ISO-3166-1 alpha-2 codes, built on `ext-intl` (`Locale::getDisplayRegion`), the reason this library requires the `intl` extension, and on `mbstring` for folding the ICU display names. Used by `PlaceProcessor`'s `CityCountry`, `CityIso2` and `CityIso3` styles.

### Modules
- **`Module/VersionInformation`** — checks GitHub releases for newer module versions, with file cache. No chart module references it directly; the library's `Traits/ModuleCustomTrait::customModuleLatestVersion()` override instantiates it (invoked by the webtrees control panel), so it is not dead code despite having no direct consumer reference.

### Contracts
- **`Contract/ModuleAssetUrlInterface`** — marker interface declaring `assetUrl(string $asset): string`. Custom modules that use webtrees' `ModuleCustomTrait` already satisfy this method via the trait; consumers add `implements ModuleAssetUrlInterface` to their `Module` class so type narrowing works for `ImageProcessor`'s constructor.

### Facade
- **`Facade/ModuleAwareDataFacadeTrait`** — injects the owning module (for asset URLs, custom module metadata) into a chart DataFacade implementation.
- **`Facade/RouteAwareDataFacadeTrait`** — extends `ModuleAwareDataFacadeTrait` with a route reference and a canonical `chartUrl()` builder for consumers that drive their AJAX updates through the chart's own routed URL.

### Traits
- **`Traits/ModuleChartTrait`** — shared chart-module helpers on top of webtrees' own `ModuleChartTrait`; consuming classes must define a `ROUTE_DEFAULT` class constant.
- **`Traits/ModuleCustomTrait`** — shared `ModuleCustomInterface` helpers on top of webtrees' own `ModuleCustomTrait`; consuming classes must define `CUSTOM_*` constants and `resourcesFolder()`.

### Catalogue
- **`Catalogue/PunctuationResolver`** finds the fuzzy entries of a `messages.po` whose source text changed in punctuation or spacing only. `msgmerge` pairs the old translation with a slightly changed source text and marks it fuzzy, and `msgfmt` leaves fuzzy entries out of the compiled catalogue unless it is told to use them (https://www.gnu.org/software/gettext/manual/html_node/Fuzzy-Entries.html and https://www.gnu.org/software/gettext/manual/html_node/msgfmt-Invocation.html), so the English source shows instead of a translation that is still right. A swap between ` — `, ` – `, ` · ` and ` - `, or a change of spaces, does not change what a translation means, so the same swap is applied to it. Every other fuzzy entry stays fuzzy and is reported for a person to judge, with its context and a bar in front of the source text when it has one. This covers plural entries and entries whose context changed as well. A translation the resolver changed is listed behind a tilde, because the order of the separators cannot prove which separator of the translation belongs to the change. Obsolete entries and blocks without a source text are never reported. The resolver reads the literals as they are written and never unescapes or escapes them. Its input is the catalogue in the canonical layout of gettext, which `CatalogueToolchain::normalise()` produces with `msgcat --no-wrap`, so a flag line, an indented keyword or a wrapped literal reaches it in the same shape whatever the file looked like. A catalogue gettext cannot read is refused by the command and left as it is. A block the resolver does not expect in that layout raises `CatalogueLayoutException` and the command refuses that catalogue and leaves it as it is, because reading it would be a guess. Do not hand-write a reader for layouts that the canonical layout already removes. A template that holds other entries than the one of the merge makes the command name the catalogue and leave it as it is. Only the separators and the space at both ends of the source text are mirrored in the translation, a run of spaces inside the text stays as the translator wrote it. The swap is applied only when the translation holds the separators of the source text in the same order, or none of the one that changed, not even its sign in another spacing, or already holds the new ones. An entry whose translation uses them differently stays fuzzy. It does not lay out a file, it returns an overlay of the corrected entries (`Resolution`).
- **`Catalogue/CatalogueToolchain`** reads a catalogue in the canonical layout and applies the overlay with `msgcat`, `msgattrib` and a last `msgmerge` against the template. The gettext tools are the only writer of a catalogue, so the layout is the one `msgmerge` produces and the file equals what a further `msgmerge` against the template writes. A catalogue is first merged once more from the template in a scratch copy and refused when that changes any byte of it, so nothing the tools would cut, join or rewrite is read unseen, and no rule of this class is hand-written in PHP. Only the resolved entries are selected for clearing the fuzzy flag, so a flag on the header stays as it is. Do not replace the tools with a PHP library that writes PO files, the reasons are in issue 82.
- **`Catalogue/FuzzyResolverCommand`** loops over the catalogues, checks and reads every catalogue through the toolchain, rewrites only a catalogue with something to resolve and counts the rest, listing the first ones per catalogue. `bin/resolve-fuzzy` is its starter and is shipped code outside `src/`. It takes the `messages.pot` and the `messages.po` files as arguments. It exits 0 when the catalogues were processed, whatever remains fuzzy, because the commit hook of a module blocks a fuzzy entry, and 1 as soon as one catalogue is refused or declined. A caller that wires it into a pipeline has to treat 1 as a failure.
- **`Catalogue/TranslationFiller`**, **`Catalogue/CatalogueEntryReader`** and **`Catalogue/WriteTranslationsCommand`** write a module's translations file into its catalogues. The reader parses a canonical catalogue into entries by key, the filler decides per entry whether it is written and refuses a form count that does not match the plural rule of the locale (taken from `Locale::create()->pluralRule()->plurals()`, the same source as `AbstractCatalogueStructureTestCase`), and the command applies the plan through `CatalogueToolchain::apply()` after the same merge check as the resolver. `CatalogueFile` holds the file checks both commands share. `bin/write-translations` is the starter of that command and is shipped code outside `src/` as well. It takes an optional `--core-owned=<file.pot>`, the translations file, the `messages.pot` and the `messages.po` files. It exits 0 when nothing was refused, 1 when a catalogue, an entry, a key or a locale was refused, and 2 when the arguments are too few.
- **`Catalogue/PrintableText`** turns text from a catalogue, a path or a tool into one line before the command reports it. It replaces the control characters of both ranges, the ASCII ones and the eight-bit ones, the characters that set the direction of a text (U+061C, U+200E, U+200F, U+202A to U+202E, U+2066 to U+2069) and the line feed, and it breaks up the `##[` opening that a CI system may read anywhere in a line, so a contributed catalogue cannot recolour a terminal or start a workflow command in a CI log. The tab stays. `Resolution` is the value object the resolver returns and `CatalogueToolException` is what the toolchain raises.
- The layer is analysed by deptrac as the isolated `Catalogue` layer, which depends on no other `src/` code. `bin/` is outside the PHPStan, Rector and phplint paths, so keep the starter free of logic.
- `tests/Catalogue/PunctuationResolverTest` pins the decisions on catalogue text. `tests/Catalogue/CatalogueToolchainTest` runs the real tools on a copy of the catalogue under `tests/fixtures/fuzzy/` (`tests/Double/GettextWorkspace` makes the copy). It pins that the result needs no further merge and that `msgfmt --check` accepts it. The fixture is a catalogue that `msgmerge` wrote with its previous-msgid option. To change it, edit an older catalogue and merge it again with that option.

### View
- **`View/SharedViews`** registers the webtrees view namespace `webtrees-module-base` (`SharedViews::NAMESPACE`) for `resources/views/`. A chart module calls `SharedViews::register()` from its `boot()`. The views take translated texts as parameters, because xgettext in the modules only sees literals in their own sources, and escape every value with `e()`. The `data-panel` parts of `detail-panel.phtml` must stay equal to what the panel script of `webtrees-chart-lib` looks up. `resources/` is not export-ignored, so the views reach the release archive. The layer is analysed by deptrac as the isolated `Views` layer. View tests live in `tests/View/` and render through the real webtrees `View` with `tests/Double/ViewFixture`.

### Testing
- **`Testing/AbstractCatalogueStructureTestCase`**, structure checks over the translation catalogues a module ships. A module extends it in its own `tests/` and implements `languageDirectory()` (the directory with one subdirectory per locale holding `messages.po` and `messages.mo`). The class lives under `src/` so a module can inherit it, which means it ships with the production code. It extends `PHPUnit\Framework\TestCase`, so PHPUnit is a dev dependency of the consumer and is never loaded at runtime. It is analysed by deptrac as the isolated `Testing` layer, which depends on no other `src/` code.
- The checks take the expected plural form count from the plural rule class of `fisharebest/localization`, the same one webtrees applies, and never from the PO header. They cover the form count and the slot count, empty forms, the `%s` and `%d` placeholders (numbered ones included), a compiled catalogue that matches its source, a complete `Plural-Forms` header line and a render of every plural entry for a range of numbers. A module without any plural string overrides `shipsPluralEntries()` to return `false`, and the two checks that demand a plural entry then demand its absence.
- `tests/Testing/AbstractCatalogueStructureTestCaseTest` runs every check against the fixture catalogues under `tests/fixtures/catalogues/`. Fixtures are either defect fixtures or guard fixtures. A defect fixture isolates one defect (`defects-after-a-clean-entry` carries two on purpose, in entries that sort after a clean one), and the test pins which checks go red for it. A guard fixture pins that no check goes red for an input that carries no defect, including inputs that only look suspicious. Examples are a clean catalogue, a path with glob characters, sources with Windows line endings (kept as such through `.gitattributes`), a doubled percent sign, a numeric message id, strings wrapped over several lines, sources that end without a final line break, a comment block before the header with an escaped quote in it and numbered placeholders in another order. `no-locales` (a directory that holds only `.gitkeep`) and the `does-not-exist` entry of the matrix (a directory that is missing on purpose, because git cannot store it) are defect fixtures without any catalogue. They fail only the checks that look at all locales. The `.mo` files of the other fixtures are compiled from the sibling `.po` with `msgfmt`, with the exceptions named below. `stale-compiled` is compiled from the `clean` source on purpose. `orphan-compiled` and the `de` locale of `orphan-next-to-complete` have a `.mo` without a `.po` on purpose, copied from the `clean` compile. `no-header` is compiled from the `clean` source on purpose, so its `.mo` keeps a header that its `.po` lacks. `missing-compiled` has no `.mo` on purpose. To change a fixture whose `.mo` is compiled from its own `.po`, edit the `.po` and compile it again. A different gettext version can write other bytes for the same content.

## Code style
- PSR-12 + PER-CS 2.x with project-specific tightenings (PHP-CS-Fixer config in `.php-cs-fixer.dist.php`).
- All files declare `strict_types=1`.
- The dev toolchain comes from `magicsunday/coding-standard` (the one `require-dev` entry besides infection and phpat): `.php-cs-fixer.dist.php`, `rector.php` and `phpstan.neon` build on its shared `php-cs-fixer/base.php`, `rector/base.php` and `phpstan/base.neon`; `phpunit.xml`, `.editorconfig` and `deptrac.yaml` are copies of its templates, kept in step by `composer ci:test:php:templates`.
- Strict PHPStan (level max + strict-rules + deprecation-rules + phpunit extension + checked exceptions, all via the shared `base.neon`, plus phpat through its opt-in `phpat.neon`) — no baseline file; findings are fixed in code, with a small set of scoped `ignoreErrors` entries in `phpstan.neon` for irreducible library-export false positives (e.g. `trait.unused` on traits only consumed by downstream modules).
- Architecture rules are split "Deptrac first, phpat only where Deptrac cannot". `deptrac.yaml` imports coding-standard's shared layer ruleset and enforces the whole layering. It adds the package's own `Processor` layer (may depend only on `Contract`, `Model`, `Support`), `Traits` layer (may depend only on `Module`) and `Testing` layer and `Catalogue` layer (each may depend on no other `src/` code). It also narrows the shared layers through **overlay layers**. Deptrac unites rulesets across imports, so a rule for a shared layer could only widen it. Deptrac also checks a class against EVERY layer it belongs to. `LeafModel`/`LeafSupport`/`LeafContract`/`LeafModule` (same directories as the shared twins, allowed nothing but themselves) therefore pin the leaf layers, and `DataFacade` pins `Facade` to `Contract`. Deptrac checks traits as well, which phpat cannot subject, so the outgoing edges of `Facade`/`Traits` are enforced too. Overlap has a price, documented in `deptrac.yaml`'s header. Every overlapped layer lists itself and its twin. Every layer depending on one lists the overlay too. Deptrac prints one "is in more than one layer" warning per overlapped class (it does not fail the run). The overlays are hidden from the graphviz layer graph so the twin/overlay alias pair does not read as a cycle. `composer ci:test:php:deptrac` runs, in order: `deptrac analyse`, `deptrac debug:unassigned` (fails on any `src/` class no layer collects, because an unassigned class is constrained by nothing), and the layer-graph cycle gate (`deptrac analyse --formatter=graphviz-dot` into `.build/deptrac-layers.dot`, read by coding-standard's `check-deptrac-cycles.php`). `tests/Architecture/ArchitectureTest.php` (phpat, run inside the PHPStan step) keeps only what Deptrac cannot express, namely that `Model`/`Support`/`Processor`/`Module` are `final` (a class modifier). `composer ci:test:php:phpat-subjects` (coding-standard's `check-phpat-subjects.php`) fails on a phpat rule whose subject selects no `src/` class, e.g. a trait-only namespace. Verify a new rule, Deptrac or phpat, by breaking it. Never assume a green run enforces it.
- Promoted constructor properties + `readonly` where applicable (Rector applies this automatically per `rector.php` set list).
- The test tree mirrors `src/`: a test lives at the path of its subject (`src/Support/Locale/IsoCountryMap.php` → `tests/Support/Locale/IsoCountryMapTest.php`) and its namespace carries the matching suffix (`MagicSunday\Webtrees\ModuleBase\Test\Support\Locale`). PSR-4 resolves this without a composer change. PHPUnit itself never checks the namespace — it requires the file and matches the class's *short* name against the filename — so a mis-namespaced test still runs and the test count will not reveal the mistake. `composer ci:test:php:psr4` (`dump-autoload --optimize --strict-psr`; Composer requires the optimisation for the strict check) is the gate that does: it exits non-zero and names the offending file. It runs inside `ci:test` and as its own CI step.
  - **Exception, files that test no `src/` subject.** The mirror rule pairs a test with the class it exercises, so it applies only to files that have one. Several kinds of file have no such subject and stay put: `tests/bootstrap.php` (harness), `tests/Bin/` (tests of the `bin/` starter, whose subject is a script and no class), `tests/Double/` (test doubles that are no test themselves), `tests/fixtures/` (data files without PHP) and `tests/Architecture/` (phpat rule providers). The phpat rule providers are not PHPUnit tests at all, are excluded from the suite in `phpunit.xml` and are consumed by PHPStan via the `phpat.test` service tag. There is no `src/Architecture/` for them to mirror. The PHP classes among them (`Bin/`, `Double/` and `Architecture/`) still have a namespace that follows the directory, so the PSR-4 gate covers them. `bootstrap.php` is a plain script without a namespace.
- Test classes are declared `final`.
- Mutation testing runs through `infection` (`composer ci:test:php:infection`, config in `infection.json5`, `src/` only). It is **not** part of the `ci:test` aggregate: that aggregate is what the pre-commit hook runs over the whole worktree, and a full mutation run is too slow to pay on every commit. The dedicated `Mutation Testing` CI step is therefore the *only* place it runs — do not remove it assuming the aggregate covers it. It is gated to one matrix leg (the score is a property of the tests, not of the PHP version) and needs a coverage driver, which `setup-php` provides via `coverage: pcov`.
- `minMsi` / `minCoveredMsi` **gate at 82**, measured with `timeoutsAsEscaped: true`. Infection counts a timed-out mutant as *killed* by default, which inflates the score — a mutation that made the suite hang is not one the tests caught; counted honestly, the score at adoption (#39) was **MSI 82.29 %** and the floor was set to 80. Removing the reflection-based tests (#40) and the fetch hardening (#42, #43) raised it to **MSI 84.44 %** at **100 % mutation code coverage** (514 mutants, 434 killed, 75 escaped, 5 timed out), so the floor was ratcheted to 82. The floor sits below the measured score because the timeout count varies with machine load and now feeds the score. There is deliberately no `maxTimeouts` hard limit on top: it would gate on that same non-deterministic quantity a second time without the surrounding score to absorb it. Raise the floor as the score improves — and never lower it to admit a regression (fix the tests instead; escaped mutants are tracked in their own issue).
- **The CI matrix is coupled three ways** — change it in one place and you must change all three in the same commit: the `php:` list, the repo's `required_status_checks.contexts` on `main` (`build (8.3)` / `build (8.4)` / `build (8.5)`), and the `mutation: true` matrix include that selects the single leg the mutation gate runs on. The job's `name:` is pinned to `build (${{ matrix.php }})` precisely so the extra `mutation` dimension does not rename those contexts. Miss the contexts and PRs hang `BLOCKED` while all checks are green; miss the include and the mutation gate silently runs nowhere.
- Every test declares its coverage target: `#[CoversClass]` for a class/enum subject, `#[CoversTrait]` for a trait, plus `#[UsesClass]` / `#[UsesTrait]` for each collaborator it actually executes (a collaborator outside the `<source>` scope — `src/` only — such as a webtrees vendor class, needs none: it records no coverage). A purely structural test that executes no production line (reflection-only API-shape checks) declares `#[CoversNothing]` rather than a `Covers*` it never exercises — honest, and it does not masquerade as coverage a mutation run would expect to kill. `phpunit.xml` sets `requireCoverageMetadata="true"`, so `composer ci:test:php:unit` fails a test that declares none (as *risky*) — this holds without collecting coverage, so the existing CI unit step enforces it.
- All code comments in English (planning docs may be German).

## Tooling parity with chart modules
Per project policy, `composer.json`, `phpstan.neon`, `rector.php`, `phpunit.xml`, `.phplint.yml`, `.php-cs-fixer.dist.php`, and `.github/workflows/ci.yml` are kept structurally identical (modulo PHP-only vs JS sections) to the canonical fan-chart equivalents at `/volume2/docker/webtrees/app/vendor/magicsunday/webtrees-fan-chart/`. When updating tooling here, mirror the change to fan/ped/des in the same session, and vice versa.

**What this rule is for, and its one exception.** The point is that a change to a config *the repos already share* must not land in one of them and be forgotten in the others — silent drift. It is not a ban on ever being ahead. **Adopting a new dev tool may run as a tracked pilot**: land it in one repo, and in the *same session* file an issue against each remaining repo describing the setup to mirror. That is the opposite of silent drift — the divergence is deliberate, visible and assigned. It is also how the shared config gets to be *right*: both phpat and infection had their leg-selection and score-accounting corrected during review of the pilot, and neither correction had to be repeated three times. A pilot without those issues filed is just drift, and is not allowed. Precedent: phpat (module-base #37 → fan #279 / pedigree #146 / descendants #135) and infection (#39 → fan #280 / pedigree #147 / descendants #136).

## Release
- Library — no asset zip, no `make release` pipeline. Releases are pure git tag + GitHub release.
- Bump consumer-facing dependencies first (e.g. when bumping `php` constraint or changing public class/interface signatures, decide on minor vs major per semver).
- After tagging, the three chart-module `composer.json` files need their `magicsunday/webtrees-module-base` constraint widened to allow the new range (e.g. `"^1.1 || ^2.0"`), then those modules ship patch releases.
- Tag/release commands:
  ```
  git tag <X.Y.Z>
  git push origin main --tags
  gh release create <X.Y.Z> --title "<X.Y.Z>" --notes-file /path/to/notes.md
  ```

## Common pitfalls
- `composer ci:test` runs phpstan with `level: max`. Never use `@phpstan-ignore` annotations — fix the code, or add a scoped `ignoreErrors` entry in `phpstan.neon` keyed by identifier and path with a rationale comment (see the `trait.unused` entries there for the pattern).
- `assetUrl()` lives on `ModuleCustomTrait`, not on any interface. Anywhere this library needs it, the parameter type uses an intersection with `ModuleAssetUrlInterface` (see `Contract/`). Never use `method_exists` to work around missing-method type errors.
- PHPUnit 12 prefers `self::createStub()` over `$this->createMock()` for tests that only need a target object for reflection-based access (no mock-call expectations).
- Cache directories live under `.build/cache/` (phpstan, rector, phpunit, php-cs-fixer, phplint); Deptrac writes `.deptrac.cache` to the repository root (git-ignored, as in fan-chart); jscpd resolves out of `node_modules/`, installed from the committed lockfile with `npm ci` and pinned to an exact version in `package.json`. CI runs it as its own job through the shared `cpd.yml` workflow of the `.github` repository, reported as `cpd / Copy-paste detection`. The canonical "force regeneration" reset is `rm -rf .build node_modules`, followed by a fresh `composer update` in the buildbox and an `npm ci` — note that this discards the installed dependencies too, so budget for the re-resolve.

## Git flow

- Commit subjects — and the pull-request title — are governed by the shared `commit-convention` gate; the normative rule and its full rationale live in `magicsunday/.github/.github/workflows/commit-convention.yml@main`, which self-tests a decision table before applying it. In short: a `GH-`-prefixed subject must match `^GH-\d+: [A-Z]`, every other subject `^[A-Z]` — a capitalised English imperative — and conventional-commit prefixes (`feat:`, `Fix:`, …) as well as path-like starts (`src/…: …`) are rejected whatever their case. It runs on every pull request via `.github/workflows/commit-lint.yml`, advisory until `commit-convention / Commit convention` is a required context in branch protection.
- Branches for an issue are named exactly `GH-<N>`; the `GH-<N>: ` prefix marks work that belongs to that issue, so a drive-by fix on the branch keeps its own unprefixed subject.
- The pull-request body closes the issue with `Closes #<N>` — the `GH-<N>: ` subject prefix is not a GitHub link and closes nothing.
- Never add a `Co-Authored-By:` trailer or any other AI attribution.
